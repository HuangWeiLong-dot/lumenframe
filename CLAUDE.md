# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

LUMENFRAME — a movie/TV detail-page SPA that aggregates metadata, ratings, cinematography specs, streaming availability, torrents, subtitles and screenshots, and renders shareable poster cards via Canvas. Three independent services in one repo; there is no monorepo tooling and no shared package.

Comments, docs, and commit messages are in Chinese — match that when editing existing code.

## Running it

Each service runs in its own terminal. Both backends are needed for full functionality; the UI hides any section whose backend is absent.

```bash
npm run dev --prefix server          # Node API → :3002 (node --env-file=.env --watch index.js)
npm run dev --prefix web             # Vite → :5173, proxies /api → :3002, /filmgrab → :8000/api
```

```powershell
.\filmgrab-service\start.ps1         # Python FastAPI → :8000 (creates .venv, installs deps,
                                     #   probes 127.0.0.1:7890 and sets HTTP(S)_PROXY if open)
```

`web/vite.config.js` is the only place the dev-proxy topology is defined. In production Nginx replaces it (`docs/deploy.md` §4.3) — the rewrite `/filmgrab/*` → `:8000/api/*` must be reproduced there.

**Build** (there is no test runner or linter configured anywhere in this repo):

```bash
npm run build --prefix web           # → web/dist
BASE_PATH='/repo/' npm run build --prefix web   # project-site subpath (build-time env, not VITE_*)
```

`web/dist` is served as static files by **GitHub Pages**. `.github/workflows/deploy-pages.yml` builds it on pushes touching `web/**` and publishes via `upload-pages-artifact` + `deploy-pages`; the repo's Settings → Pages **Source must be set to "GitHub Actions"** (not "Deploy from a branch"). It reads repo Variables `API_BASE` / `FILMGRAB_BASE` / `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` (the variable names have no `VITE_` prefix — the workflow maps them onto the `VITE_*` names the code reads) plus the Secret `PLAY_PASSWORD`, and pins `node-version: 22` (≥22 is mandatory — `@supabase/supabase-js` requires it; the last version supporting 20 is 2.105.0). **`BASE_PATH` is empty by default, which yields `/`** — `vite.config.js` is `env.BASE_PATH || '/'`, and an apex custom domain wants exactly that. Serving from the `github.io/<repo>/` subpath instead means setting the `BASE_PATH` **Variable** to `'/<repo>/'` — it **must be absolute**; a relative `'./'` white-screens every deep link while the homepage keeps working, because `index.html`'s inline `<head>` script runs `replaceState` back to the deep path *before the body is parsed*, so the later `<script src="./assets/…">` resolves against the new document URL (`/movie/assets/…` → 404 → no JS at all). Absolute paths are immune; see the longer note in `deploy-pages.yml`; `getBasePath()` handles the rest at runtime. **A misspelled `VITE_*` name fails silently** — the bundle gets `undefined` and the feature self-hides exactly as if unconfigured, so after changing a Variable, grep `web/src/` for the `import.meta.env.*` name being set. (That bit us on Cloudflare: a variable was created as `VITE_SUPABASE_PUBLISHABLE` with no `_KEY`, and the whole cloud-sync feature vanished with no error anywhere.)

> ⚠️ **This only works while the repo is public.** Publishing Pages from a **private** repo requires Pro/Team/Enterprise; on GitHub Free a private repo takes the site down instantly, and the failure looks like a generic 404 (`Server: GitHub.com` response header) with no clue in the workflow logs. This actually happened on 2026-09-20 — see the `deploy-pages.yml ↔ Cloudflare` detour below. Making the repo private again requires upgrading the plan *first*.

**Was Cloudflare (Workers + Git integration) between 2026-09-20 and the same day**, adopted only because the repo had been made private. Reverted to Pages once the repo went public again, and the Cloudflare-specific bits — `web/wrangler.jsonc` (the Worker's `assets.directory`, since a Worker has no "Build output directory" field) and `web/public/_headers` — were removed with it; both are still in git history (`8a6ee94`, `edeae5d`) if that path is ever needed again. Two things are worth keeping from that detour: the `.gitignore` fix for `Torrent-Api-py`'s **dangling gitlink** (it broke Cloudflare's clone, which recurses submodules — `actions/checkout` does not, which is why Pages never hit it), and the fact that **`_headers` is a Cloudflare-only mechanism**. GitHub Pages ignores it entirely and hardcodes `Cache-Control: max-age=600` on every asset, so `/assets/*` revalidates every ten minutes instead of being immutable for a year — a real (if minor) regression, and not fixable while on Pages.

**The backends deploy by SSH push.** `.github/workflows/deploy-server.yml` fires on pushes touching `server/**` or `filmgrab-service/**`: it SSHes in as `root`, runs `git fetch` + `git reset --hard origin/main`, `npm ci` (server) and `pip install` (the filmgrab venv), restarts `lumenframe-server` / `lumenframe-filmgrab`, then polls `127.0.0.1:3002` and `:8000` under a bare `curl` — no `-f`, so *any* HTTP answer including 404 counts as "port is listening", while a port that never answers fails the run. Needs repo Secrets `SERVER_IP` / `SERVER_USER` / `SSH_PRIVATE_KEY` (optional `SSH_PORT`, default 22). That in turn requires the host's security group to allow inbound 22 from `0.0.0.0/0`: GitHub's runner pool spans ~6900 CIDRs (`api.github.com/meta` → `actions`) and a Tencent Cloud security group caps at 100 rules, so an allowlist is impossible and root SSH is exposed to the whole internet — `PasswordAuthentication no` is load-bearing, not hardening. The `git reset --hard` discards hand-edited *tracked* files on the box; `.env`, `server/.cache/` and `docs/` are gitignored and survive. A pull-based alternative (`deploy/` + a systemd timer polling `origin/main`) was tried and dropped: it must be installed on the box by hand and reports nothing back to Actions.

**Env files** (all gitignored): `server/.env` (`TMDB_API_KEY` required; `TMDB_PROXY` only for restricted networks like China; optional `SOURCES_PROXY` — the play-sources scrapers' own proxy, see below; `PORT`; optional `PLAY_SOURCES=1` to enable the online play sources — it also needs a `server/sources.json`, see `server/sources.example.json` and `docs/play-sources.md`), `filmgrab-service/.env` (`YOUTUBE_API_KEY`, optional `PYTORRENT_API_KEY`, `HTTP_PROXY`/`HTTPS_PROXY`, `PROXY_CONCURRENCY`). `web/` has no runtime env — only build-time `VITE_API_BASE` / `VITE_FILMGRAB_BASE` / `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` / `VITE_PLAY_PASSWORD` (see `web/.env.example`; the last one is fed from a repo **Secret** of the same name, not a Variable). There is no CI build step any more — Cloudflare's Git integration builds — so a new `VITE_*` var stays `undefined` in the bundle until the CI build step enumerates it by name **and** a matching repo Variable exists. The Node version is likewise a workflow input (`node-version: 22`), not a variable.

## Architecture

### Service boundaries

| Service | Port | Owns |
| --- | --- | --- |
| `web/` | 5173 dev | React 19 + Vite + Tailwind v4 SPA |
| `server/` | 3002 | Everything TMDB-centric: search, details, images, ratings, specs, watch availability, TVmaze shows, subtitles |
| `filmgrab-service/` | 8000 | FilmGrab screenshots, YouTube trailers/comments, torrent search (16 sites) |

The split is deliberate, not incidental: anything requiring browser-TLS impersonation, Python scraping libs, or that must not be publicly deployed lives in `filmgrab-service/`. `server/index.js` handles only what plain `fetch` + API keys can do.

`server/api/index.js` re-exports the Express app for serverless hosting (`server/vercel.json` was removed from the working tree; the documented paths now are Linux+Nginx and GitHub Pages+separate API host).

`Torrent-Api-py/` is a standalone upstream checkout kept for reference. Its `routers/`, `torrents/`, `helper/`, `constants/` are **vendored verbatim** into `filmgrab-service/` — the `.py` files are byte-identical. Fixing a torrent scraper means editing the copy under `filmgrab-service/`, not the upstream tree.

### Frontend (`web/src`)

- **Router**: no React Router. `App.jsx` hand-rolls the History API: `/movie/{tmdbId}-{slug}`, `/tv/{tvmazeId}-{slug}`, `/person/{id}-{slug}`, `/genre/{kind}/{id}-{slug}`, `/discover`, `/discover/{movie|tv}`, `/library`. `id` is authoritative, slug is cosmetic. `BASE_PATH` is derived at runtime from `location.pathname` (`getBasePath()`) so deep links work both at `/` and `/<repo>/`.
- **The 404 dance is what carries deep links**: `web/public/404.html` encodes the original path into `_spa=` and bounces to the root; an inline script in `index.html` and `resolveSpaRedirect()` in `App.jsx` unwrap it (recursively, up to 20 levels) before React mounts. Break one and deep links 404-loop. GitHub Pages serves a top-level `404.html` for every unmatched path, so this works unchanged — and so did Cloudflare, which is why **both host migrations touched no routing code**. On Cloudflare the equivalent behaviour had to be opted into explicitly (`wrangler.jsonc`'s `not_found_handling: "404-page"`); its *native* SPA fallback (unmatched paths return `/index.html` with a 200 and no redirect) was deliberately **not** used, because it would mean deleting `404.html` and unwinding a three-file contract whose failure mode is a total deep-link breakage, to save one redirect and a 404 status code.
- **i18n** (`web/src/i18n/`): custom, not react-i18next. `useSyncExternalStore` over a module-level `lang` + `localStorage['lumenframe:lang']`. Two facts matter: `t()` falls back to English then warns on a missing key (so add keys to **both** `en.js` and `zh.js`), and `apiLang()` is the non-reactive accessor used by `api.js` while `useI18n().apiLang` is the reactive one components put in effect deps.
- **Discover page (`DiscoverPage.jsx`, 「影片索引」)**: B站-style filtered index — sort row (热门/最新/高分/评价数), region/genre/decade filter panel (right sidebar on lg+, collapsible behind a 筛选 button below), poster grid with Load-more. Filters and sort live in **component state**; the URL carries only the kind tab (`openDiscover` pushes `/discover/{kind}`), so a deep link restores the tab but not the filter combo. Switching kind resets `genre` (movie/tv genre ids are two separate id namespaces) while keeping country/decade/sort.
- **Data fetching**: plain `fetch` in `useEffect`. **Do not use `AbortController`** — React 19 StrictMode double-mounting produces `net::ERR_ABORTED` console noise. The house pattern is `const t = setTimeout(0, …)` + an `alive` flag that discards stale responses, and a 15s `Promise.race` timeout in `Torrents.jsx`.
- **Home-page prefetch is a three-file contract.** `useTrending` reads `window.__lfTrending`, which is not set by any module in `src/` — it is injected into `<head>` as an inline script by the `homePrefetch` plugin in `web/vite.config.js`, at build time, with `VITE_API_BASE` baked in as a literal. The point is to start `/api/trending` during HTML parse rather than after the ~115 KiB main bundle downloads and executes (Lighthouse measured that gap as 1,720 ms of LCP). It must stay inline: a separate `<script type="module">` entry either costs its own request or gets inlined into the main chunk by Rollup, which defeats it. It resolves to `null` on failure (not `[]`) because `useTrending` only writes its module-level cache for an array, so a failed prefetch can be retried on a later mount. If you remove the plugin, `useTrending` falls back to its own fetch — nothing breaks, the prefetch just stops happening.
- **Both webfonts are self-hosted** (`@fontsource-variable/inter` + `@fontsource-variable/noto-sans-sc`, imported in `main.jsx` before `index.css`). Never reintroduce a `fonts.googleapis.com` `<link>`: it is render-blocking and third-party, and in the CI/Pages build it was costing ~1.5 s of critical path. The one deliberate exception to "use `--font-sans`" is `.font-system-cjk` (`index.css`), applied only to the Chinese option inside `LanguagePicker` — that modal is on screen for every first visit and was the sole source of Chinese glyphs on an English page, pulling ~380 KiB of Noto subsets. It is safe there because that text uses only weights 400/700, which system CJK fonts actually have.
- **`onIdle` (`web/src/idle.js`) returns a cancel function**, not a handle, and falls back to `setTimeout` where `requestIdleCallback` is missing (Safari < 15.4, and Node — `web/scripts/sim` runs the real sync engine there). Use it for work that must not compete with first paint. **`initSync()` must never be deferred**: it installs the change recorder, and its current position in `main.jsx`'s module body — before React mounts — is what makes the "recorder not yet listening" window exactly zero. Widening that window means a delete during it records no tombstone and gets resurrected by the next cloud pull. `initAuth()` is safe to defer (it is only what pulls the ~59 KiB supabase chunk) and is.
- **Sections**: every detail-page block is wrapped in `CollapsibleSection` and receives `key={movie.id}` so switching titles fully resets state. When a service is unconfigured or errors, the section returns `null` rather than an error state.
- **Cards** (`Card.jsx` + `canvas-utils.js`, driven by `CardStudio.jsx`): Canvas is repainted imperatively from React state (`preview ≡ export`, no DOM screenshotting). 5 templates × 5 aspect ratios. Image loading goes through `web/src/imageQueue.js` (global 8-slot concurrency gate) to avoid saturating the image proxy. **Do not make this a no-op.** `SmartImage`'s 8 s timeout only starts counting once a slot is granted, so without the gate a gridful of posters starts timing out while the browser's ~6-connections-per-origin cap still has them queued — each timeout fires a `_r=` retry, and the doubled request load both blanks the images (`No poster`) and blows up the proxy's memory until it exits, which the browser then sees as 500s.
  - **Every `acquireSlot()` needs an effect-run-scoped cancel flag, not the shared `cancelledRef`.** StrictMode's double-mount is *mount A → cleanup A → mount B*, and it is **B** that resets `cancelledRef` to `false`. So when the queue is contended and `acquireSlot()` is still pending across that boundary, A's promise resolves into a `cancelledRef` that is already `false`: it claims the slot and writes `releaseRef`, then B's promise **overwrites** `releaseRef` and A's releaser becomes unreachable — a permanently leaked slot. Eight of those and the queue stops dead (measured 2026-09-25: `active: 8, waiting: 120`, only 10 of 65 stills ever got a `src`, and the page's own images froze with it). Both `SmartImage` effects therefore hold a local `disposed` flag. This was latent for as long as the queue existed — it needed a caller mounting dozens of images at once (the stills grid) to become visible, so if you add one, watch `queueStats()`.
  - `SmartImage`'s `lazy` prop (default `true`) exists for the opposite case: a set the user explicitly opened and that will all be looked at. With `loading="lazy"` still on, an off-viewport image holds a slot **without issuing its request**, so the 8 s timeout fires and the tile is wrongly marked failed. Pass `lazy={false}` there and keep the mounting itself conditional instead.
- **Persistence**: `useLibrary.js` (watched / watchlater / likes / notes + Chart.js stats) and `usePinned.js` (pins) are `useSyncExternalStore` stores over localStorage. Keys are namespaced `lumenframe:*`, with a `storage` listener for cross-tab sync. Movies (TMDB ids) and shows (TVmaze ids) share a numeric space — entries are keyed `` `${kind}:${id}` `` and legacy rows without `kind` are migrated to `movie` on read. Every read/write is wrapped in try/catch (see `web/src/storage.js`) because localStorage can be disabled outright. Note the `-change` window events (`lumenframe:library-change`, `lumenframe:lang-change`) are **listen-only** — nothing in the repo calls `dispatchEvent`, so the `subscribe` fan-out for them is dead; build on the exported `subscribe*` functions instead.
- **Pin cap**: `MAX_PINS = 6` is enforced at **render** time (`usePinned` returns `store.slice(0, MAX_PINS)`), never at write time. Slicing on write would make pinning a 7th title look like a user deletion to the sync layer, which then tombstones it and lets a second device push it back.
- **Cloud sync (optional, Supabase)**: email+password auth plus multi-device sync of the library, client-only — the browser talks to Supabase directly with a publishable key, and RLS is the entire security boundary. **Neither backend is involved.** `web/src/supabase.js` is the config switch: when `VITE_SUPABASE_URL`/`_PUBLISHABLE_KEY` are absent the whole feature self-hides (no account button, no requests, and supabase-js stays in an unloaded chunk — same rule as `FILMGRAB_BASE === ''`). `web/src/sync/engine.js` runs a full pull → merge → push cycle; `sync/projection.js` and `sync/merge.js` are pure and are exercised by `node web/scripts/check-sync.mjs`; the engine's *wiring* (subscription order, when the recorder stamps, snapshot-after-await) is exercised by running the real engine in Node against an in-memory Supabase — `npm run sim` / `npm run sim:wipe --prefix web`, see `web/scripts/sim/README.md`.
  - **`getSupabase()` must stay lazy.** `App.jsx`'s `resolveSpaRedirect()` is module-scope code that runs *after* its imports are evaluated; a `createClient` in a module body would consume `window.location` before `_spa` is unwrapped, and the email-callback session would silently never establish.
  - **The synced projection excludes `ratings`.** It is a re-fetchable third-party cache that `loadRatings` (every detail-page visit) and `refreshAllRatings` rewrite constantly; syncing it would republish titles on every page view.
  - **Deletes are tombstones** (`deleted_at`), and the local half lives in `lumenframe:sync:meta` as `{ [listKey]: { ts, deleted? } }`. Timestamps are recorded by a subscriber at the moment a store changes — never derived from the entry shape. Seeding uses `addedAt` so pre-existing entries don't all look newer than the cloud.
  - **One sync may not tombstone most of the account.** `merge.deleteImpact` counts how many *live* remote rows this round would delete; `isBulkDelete` fires at ≥10 **and** >half of them, and `heldBackKeys` then holds back just the deletions (adds/edits keep pushing), parking the status at `guard` and asking the user to confirm — a second click on 「立即同步」 (`requestSync` sets a one-round `forceDeletes`). The tombstone stays in `sync:meta`, so an unconfirmed wave re-triggers every round; that is intended. Deletions are the only thing that can destroy another device's data (see the 2026-09-18 wipe), and a poisoned `sync:meta` can't be prevented at the source — only bounded here. This guards the **push** direction only: a cloud full of tombstones still empties local on pull, and only the SQL cleanup fixes that.
  - **Only this page's own `write()` may create a tombstone.** The stores tag each notification with an origin (`setChangeOrigin` in `storage.js`): `emit()` — the `storage`-event re-read — is `external`, and `recordChanges` refuses to delete on those. An external wipe (the user clears site data, another tab calls `clear()`) then degrades to *"local cache is empty → restore from the cloud"*, never to *"the user deleted all 50"*. Recording them as deletions pushes an entire library's deletion as authoritative — one cleared device permanently destroys every other device's data, and the fresh page that logs in next sees only the handful of items added after the wipe. The same rule is what `buildLocalState` already relies on for "meta says alive, projection is empty".
  - **`sync:meta` is shared across tabs; the in-memory copy is not.** `persistableMeta` merges per key against the on-disk copy on every write (wholesale assignment lets tab B's stale copy erase tab A's fresh tombstone → the deletion resurrects), and `syncMetaFromDisk` merges it back into memory before each merge — necessary because `ensureLeader` means the tab holding the lock may be judging someone else's deletion from a stale copy.
  - **`likes` are addressed by `entry.type`, not `entry.kind`** — a genre like carries the movie/tv kind it belongs to, so keying on `kind` collapses every movie-genre like into one row.
  - **Take every local snapshot *after* the network round-trip.** `syncNow` awaits `pull()`; reading `currentLocal()`/`project()`/`meta.meta` before that await and writing the result back wholesale erases anything the user did in between — and worse, pairs a *fresh* timestamp with *stale* content, which last-write-wins then pushes to the cloud as authoritative.
  - **Write meta back per key** (`applyMetaWriteBack`), never by wholesale assignment: the recorder may have logged a tombstone during `push()`, and clobbering it silently resurrects the deleted item on the next cycle.
  - **`sync:meta`'s `scope` may only be discarded when it names a *different* account.** `scope === null` means guest data the user is now adopting; dropping its tombstones would undo deletes made before signing in.
  - **The username is a display name in `auth.users.raw_user_meta_data`**, written at signup via `options.data` and edited with `updateUser({ data })` (which merges, not replaces). Deliberately **not** a `profiles` table: no uniqueness is wanted, so there is no unique index and no duplicate-name race to handle. Moving to a real handle later means a table + unique index + migration.
  - **Never put a secret/service_role key in `web/`.** Schema (table, RLS policy, index) is `supabase/schema.sql`, run once by hand in the Supabase SQL editor.

### Node backend (`server/`)

`index.js` is the TMDB proxy + routers; scrapers live in sibling modules — `ratings.js` (OMDB + Rotten Tomatoes Popcornmeter), `sow.js` (ShotOnWhat? tech specs), `tastedive.js`, `tvmaze.js` (TVmaze, English-only and deliberately ignorant of TMDB), `tvmeta.js` (the TVmaze→TMDB overlay that gives shows Chinese metadata), `subtitles.js` (OpenSubtitles), `rt.js`, `titlematch.js`, plus the `sources.js` pair `nbparse.js` (pure HTML→data, offline-testable) and `nbsign.js` (the only module that loads the vendored 4kvms wasm — see the Play sources bullet).

- **Language**: every text endpoint takes `?lang=`; `reqLang()` whitelists `en-US|zh-CN|zh-TW` and collapses other `zh*` to `zh-CN`. Cache keys are language-scoped via `lk()` (`movie:157336:zh-CN`) — omitting it lets English and Chinese responses overwrite each other. Endpoints deliberately hard-pinned to `en-US`: TasteDive, ShotOnWhat, Rotten Tomatoes, and `/api/trailer` (ranking depends on the English "Official Trailer" label). Watched: `englishTitleByImdb` / `englishTitleByTmdbId` resolve non-ASCII titles back to English before calling those services.
  - **TV shows are localized too, and `tvmeta.js` is how** (`/api/tv/:id`, `/api/tv/search`, and the TV half of `/api/search`). The show's identity stays the **TVmaze id** — routes, deep links, library keys and pins are all keyed on it, so nothing migrates; the module only *overlays* TMDB's `title`/`overview`/`genres` onto the TVmaze payload. Resolution is by **external id** (`externals.imdb`, then `externals.thetvdb`), never by title search: `神探夏洛克` has both a BBC show and unrelated same-named ones, and only imdb/tvdb disambiguate. `title_en` is the TVmaze name and is **load-bearing** — see the `title_en || title` gotcha below. Every failure path returns the English payload rather than throwing, because localization is additive. Two consequences worth remembering: `genres` must ship **positionally aligned `genre_ids`** (the frontend's `genre_ids[idx]` fallback is what makes the chips work once the names are Chinese), and the cache is layered — `tvshow:{id}` for the raw TVmaze payload (language-independent, so switching language never re-hits TVmaze), `tvshowzh:{id}:{lang}` for the overlay, and underneath those `tvfind:{showId}:{lang}` (the id lookup, a few hundred bytes) and `tvdetail:{tmdbId}:{lang}` (only the detail page needs this one, for genre *names* — `find` returns only `genre_ids`). The search path deliberately stops at `tvfind`, so a search costs one TMDB call per result, not two; that matters because `cached()` is a single global 200-entry FIFO shared with every movie detail and image. The frontend side of this has three touch points: `App.jsx`'s detail fetch uses `apiUrlWithLang` for TV, the `apiLang`-change effect **must not** skip `kind === 'tv'` (it did, before), and `LibraryPage`'s language-switch backfill must cover `kind: 'tv'` — but with a **separate dedup set** from movies, since the two share one numeric space and `movie 335` would otherwise be mistaken for `tv 335`. `/api/tv/:id/episodes` and the season/episode names inside the payload are still TVmaze English.
- **Caching**: `cached(key, fetcher)` is a 30-min in-memory `Map` (FIFO, 200 entries) with single-flight dedup via `inFlight`, so concurrent cold requests hit upstream once. Scraped ratings/specs persist to files under `server/.cache/` (gitignored, auto-redirected to `/tmp` on serverless); edit `CACHE_VERSION` in those modules to invalidate a schema change.
- **`/api/discover/:kind` is a whitelisted TMDB-discover proxy — and for TV it must resolve ids.** Query params are validated against fixed sets (`genre` numeric id, `country` from `DISCOVER_COUNTRIES`, `decade` key → date `gte/lte` ranges, `sort` key); nothing is passed through raw. Two upstream quirks are handled: `with_origin_country` is honored by TV discover but **silently ignored by movie discover** (degrades to "all", not an error), and the `newest` sort caps the date at today so unreleased entries can't lead the list. For `kind=tv` every result's TMDB id is resolved to a **TVmaze id** before shipping (`tvmazeIdFromTmdb`: TMDB `external_ids` → TVmaze lookup; cached per TMDB id as `tvresolve:{id}`, with `0` = unresolvable cached too) — `/tv/{id}` routes, library keys and deep links are TVmaze-keyed, so passing the TMDB id through would open a *different* show. Unresolved items ship `id: null` and the frontend renders them as non-clickable cards rather than wrong links; resolved ids are deduped per page (two TMDB entries can map to one TVmaze show). **TVmaze's `/lookup/shows` answers a *hit* with `301 → /shows/{id}`, not 200** — `httpsGet` doesn't follow redirects, so `lookupShowId` (tvmaze.js) parses the id straight out of the Location header; a miss is a plain 404. The per-show resolution is cached independently of the per-page cache, so repeat visits to the same shows under different filter combos pay nothing.
- **Images**: `/api/image?path=&s=` proxies `image.tmdb.org`. There is **no** server-side binary cache by design (w1280/original can be megabytes) — only `imgInFlight` dedup plus `Cache-Control: immutable` for the browser. `setDefaultResultOrder('ipv4first')` exists because IPv6-less cloud hosts make `fetch` fail outright.
- **Play sources** (`sources.js`, mounted at `/api/sources`): liveness probing, search aggregation across MacCMS (苹果CMS) collection sites, and parsing-endpoint round-robin. Gated on `PLAY_SOURCES=1` **and** a `server/sources.json`; either missing → every route answers `{"enabled": false}` and the section self-hides (same contract as `FILMGRAB_BASE === ''`). **Every request here goes out over `node:http`, not `fetch`** — deliberate, so the ~60 domestic collection sites aren't dragged through the `TMDB_PROXY` dispatcher (see `nbsign.js`), but it also means neither that dispatcher nor `HTTP_PROXY` applies. 4kvms is the exception that proves the rule: it is blocked from mainland IPs (`www.4kvms.com` resolves to `115.89.129.251` and answers a generic 404; the same URL through a proxy is 200), which is why the 「主源」 card silently disappeared on a China-network box. So `httpGet` now tries direct first and **falls back to `SOURCES_PROXY` (or `TMDB_PROXY`) on failure** — a non-2xx counts as failure, because a blocked site is precisely the one that answers fast and wrong — and memoizes the verdict per host so only the first attempt pays. `probeGet` opts out of the fallback: the prober's ~100 targets aren't worth a second attempt each, and its `ok` only ever meant "the list endpoint answered". Both vars unset (production) → pure direct, identical to before, which is what keeps the overseas box working. `sources.json` adds two more `kind`s beyond `cms`/`config`/`parse`. `"direct"` is a hand-bound per-title stream (`entries[]` of `{tmdb, title, url, label}` bound by **TMDB id** — and since `/api/movie/:id` has no `kind` field, keying on `kind === 'movie'` matches nothing; the test is `kind !== 'tv'` — with bare title as fallback, the only route for TV, whose ids are TVmaze's). Direct entries never enter `sources`, never get searched or probed, are shipped whole in `/api/sources`, and render as a pinned 「主源」 card above the search list; `enabled` is true if there are **either** collection sites or direct entries, and the frontend tracks "can search" separately so a direct-only config does not show a search box that never returns. The point is sources that cannot be found by searching at all: a site with no `api.php`, where the address can only be read out of the Network panel by hand. (`4kvms.com` used to be that example — it is the `"nb"` source below now, so `direct` is down to "only this one title, only this one address".) `"nb"` is that 4kvms source and is the opposite case: searchable. Its config line is `{ "name": "4kvms", "kind": "nb" }` and carries **no address** — the origin is built in, so the row is a switch and a label only. It is **double-gated**: the row must exist *and* `server/vendor/nbmovie/` must hold both files; either missing and the row is **silently skipped**, so a deployment that forgot the files looks like "4kvms isn't in the list", not like a crash. Those two files **are committed** (since 2026-09-20 — they were gitignored and hand-copied before, which meant `git reset --hard` never delivered them and every new box silently lost the source; `sources.json` stays ignored because it is configuration data). The chain is scrape-only because the site has no API at all: `GET /search?q=` (cards → slug/title/year) → `GET /play/<slug>` (HTML → `userlink` access token + one anchor per episode, each with `dataid` and its own `/play/<secret>`) → `build_play_url()` from the site's **own** wasm → `/video/play?p=&v=&q=&s=&t=&k=` → JSON `data.quality_urls[].url` is the m3u8. Four things are load-bearing. The signature is **f(dataid, secret, current ms)** — quality, the token and the page's `<meta id="nb-st">`/`nb-plt` are *not* inputs, and `t` is taken fresh by the wasm each call, so a long-running process inits the wasm once. Reimplementing it was tried and abandoned: 87,920 token permutations × 10 separators × md5/sha1/sha256 against a known sample produced no hit, which is why the vendored wasm exists at all. **Business errors arrive inside HTTP 200** — `q=4k` is `code:403` (client-only), `720`/`480` are `code:401` (VIP), and **only `q=1080` is usable** (also the site's own default), so test `j.code`, never `res.ok`. A missing token is HTTP 401「请提供访问令牌」, distinct from a bad signature (「不好意思，请稍后再试」); one play page's token resolves **all** of that page's episodes (7/7 measured), so detail resolves a whole season in one pass. And nb rows are pushed into `merged` **outside** the `片名|年份` grouping — merging would bury a direct m3u8 among same-scored collection rows and lose the one thing that separates them (no parse site in between); the `mirrors` array still ships but **nothing renders it** (the 「另 N 个来源」 chip was deleted 2026-09-19, together with 「N 条线路」 — both only repeated the server's own bookkeeping, and the line count is not even knowable before `keepPlayable` runs). Search rows carry `kind` (`cms`/`nb`), and the frontend promotes **one** `kind === 'nb'` row to the pinned 「主源」 card: the exact-title one (`score === 1`), else the first `score >= 0.8` row whose `year` matches the page's ±1. The year is the only signal that separates the two 0.8 buckets — nb returns the show's seasons as `庆余年 第一季`/`狂飙: 第1季` (year matches, promote) alongside genuinely *other* titles like `流浪地球2` and `流浪地球：飞跃2020特别版` (year differs, keep in the list), and requiring `score === 1` alone would leave every season-only show (庆余年, 狂飙, 神探夏洛克) with no 主源 card at all. Only one row is promoted because 神探夏洛克 arrives as five 0.8 rows sharing the 2010 badge. Promoted rows get no source number (numbering one would make the list start at 「来源 2」). `direct` cards stay above nb cards not by priority but by layout: `direct` comes from the manifest and is there instantly while nb only lands after the search round, so putting nb first would shove the hand-bound card down when it arrives. Two display rules live entirely on the frontend (`PlaySources.jsx`, plus `web/src/playMedia.js` for what the player also needs), and both **delete rather than explain**: `keepPlayable()` drops lines whose episodes are all web-page URLs (the ffzy `feifan` and hhzy `hhyun` families — measured 2026-09-19: 庆余年 loses 5 of 12 lines, 神探夏洛克 4 of 12), which leaves `play.notStream` reachable only on hand-bound `direct` entries, where hiding it would just look like the binding vanished; and a card whose detail yields nothing (every line filtered out, or the detail request itself failed) retires via `onEmpty` into a `hidden` Set — render-layer **only**, never by deleting from `data.results`, because source numbers are assigned in result order and removing one row shifts every later number. `keepPlayable` filters on `notStream` only, **not `insecure`**: http-on-https depends on the *page's* protocol, so filtering it too would give dev and Pages two different line lists. Type/status/quality are normalized server-side by `server/playlabels.js` (`type_name` → 类型; `vod_remarks` split into a 状态 axis and a 画质语言 axis; `remarks` still ships raw for troubleshooting and nothing renders it). Three rules govern those tables: **normalize the wording, never the fact** (更新至 39 集 and 完结 must stay different), infer 正片 for **films only** when nothing but a quality label was recognized (a series' HD is just a quality tag, so it must not become 正片), and pass unrecognized values through verbatim. Output order comes from the rule tables, not from appearance order — `HD中字|国语` and `HD国语中字` are the same fact and have to normalize to the same string. It lives here, not in the Python service, precisely because it must be usable from the public frontend deployment — all it needs is plain `fetch`. Read `docs/play-sources.md` before touching it; the load-bearing parts are: TVBox configs are **JSONC**, not JSON, so `parseLooseJson` repairs comments, raw control characters inside strings, and non-JSON prefixes (and it must **strip comments before locating the start bracket** — the reverse order gets fooled by a `[…]` inside a comment); title matching has its **own** `matchScore`/`normName` keeping `\p{L}`, because the shared `titlematch.js` normalizes with `/[^a-z0-9]+/g` and erases CJK entirely (`titleScore('流浪地球','三体')` is 1.0 there); the cold-cache search must **not** run concurrently with its background probe — sharing the 24-slot limiter between ~60 searches and ~110 probe targets saturates the link until the 5s per-site timeout kills nearly every search (it cost 60 sites → 1 result; serialized it is 60 → 17); repeated `q` values are issued as **separate** upstream queries with early stop, never joined into one keyword (joining them drops a site from 17 hits to 3), and the warm-path site list must come from the probe's expanded set (`probe.cmsTargets`), not from `sources.json` — config-derived sites exist only in the former, so filtering the file list by "probed alive" makes the warm round narrower than the cold one. Two more that bite: **every `name`/`sourceName` leaving the API is an alias**, a 5-char base36 hash of the source `id` (`aliasOf`), applied **at the route layer only** — never inside `loadList` or the caches, because those objects need the real `host` for dedup (`dedupKeyOf`, and `buildProbeTargets`'s `seen` set) and aliasing in place lets two different sites collide into one "duplicate". It is display-layer masking, not anonymisation: `sourceId` is still host-derived and `openUrl` is still a real domain. And `doDetail` must fall back to `cacheProbe.peek('all').cmsTargets` when a `sourceId` is not in `loadList()` — config-derived sites (36 of 96 probe targets) live **only** in that cache, so without the fallback search returns rows whose detail page is permanently empty. In-page playback (`VideoPlayer.jsx`) feeds `episodes[].url` straight to `<video>`: measured 6/8 CDN hosts answer with `Access-Control-Allow-Origin: *`, so there is **no server-side stream relay** — that would make the API host carry full-length video bytes, and it cannot fix the two failures that did occur (expired cert, timeout). Native HLS is only ever *attempted*, never *trusted*: `canPlayType('application/vnd.apple.mpegurl')` is the entry test, but Chrome 153 (Windows) answers **`"maybe"`** for it and then fails a TS-based playlist outright with `MediaError.code === 4` / `NETWORK_NO_SOURCE` — manifest 200, correct `Content-Type`, `ACAO: *`, and still nothing plays, because desktop Chrome cannot demux MPEG-TS HLS. So the `<video>` `onError` (HLS url + code 4 + not already forced) flips `setForceHls(url)` — keyed by **url**, not a boolean, so switching titles clears it — and the effect's `[url, fail, forceHls]` deps re-run it down the hls.js path; only a second failure is reported. Safari/iOS play natively on the first try and never load hls.js; Chrome pays one wasted manifest fetch before falling back to the dynamic `import('hls.js/light')` (118 KiB gzip, **not** in `index.html`) — the light build does keep AES-128 decryption, verified against a 2480-fragment encrypted playlist, so do not swap it for something smaller. Every segment request goes out with **no Referer** (`FetchLoader` + `fetchSetup` adding `referrerPolicy: 'no-referrer'`; hls.js has no config for it, and `XhrLoader` cannot set it): `sns-open-qc.xhscdn.com` answers 206 to *no* Referer and to `www.xiaohongshu.com`, and 403 to everything else including our own origin — which is what `strict-origin-when-cross-origin` sends by default, so the manifest loads and every segment fails. Measuring a source by whether its playlist loads is how that got misdiagnosed as "dies at 1m30s"; Safari/iOS take native HLS and bypass this fix entirely (`<video referrerpolicy>` does **not** help — measured: default, `referrerpolicy`, and `crossorigin` all still send `Referer` in Chrome; only `fetch(…, {referrerPolicy:'no-referrer'})` sends none — so such a source is simply unplayable there, a known limitation rather than an untested guess). `prepareSource()` also rewrites the `/ets/<ts>-<hex>/<base64>` wrapper a few playlists put around *individual* segments (56 of 1691 on the `oss.douyinbit.com` playlist the `"nb"` source hands out — same host as the segment check above, all 404, base64 decodes to the live CDN URL) — per-host memoized so clean hosts pay nothing, and it bails to the original URL unless every remaining non-comment line is absolute, because relative lines in a blob resolve against the blob address. The UI is split into two surfaces: `PlaySources.jsx` only **selects** (title → feed → episode) and `VideoPlayer.jsx` only **plays** — a stage that is **always rendered at the bottom of the section**, idle copy and all. It must sit outside every `ResultCard` (cards collapse and several can be open, so a card-hosted player eventually runs two `<video>`s at once). Because the stage is *below* the list, it calls `scrollIntoView({ block: 'nearest' })` on mount. **Do not clear `playing` when the search effect re-runs**: a different film already remounts the whole component via `key={play-${movie.kind}-${movie.id}}`, while a re-search of the *same* film (the widening pass, or 「重新搜索」) is exactly the case where the user may be mid-episode — clearing there just kills playback he asked to keep. The stage has an **episode picker of its own** (`n/N` in the control bar → a grid above it), so the item handed to `onPlay` carries the whole `episodes` array and `epName`, and `onSwitch` swaps only `url`/`epName` — the header line and the picker then stay true without re-deriving anything. Both surfaces label episodes through `epLabel` in `web/src/playMedia.js`, because two independent labelings of one source read to the user as two different episode lists; feed names get the same treatment (线路一、线路二 via `cnNumber`, with the site's own codename kept as the button's `title`) — a station's internal feed codename is unreadable and unmemorable, and the only thing a user is choosing between is which one it is. That module also holds `playBlocker`/`canPlayInline`/`keepPlayable`, shared so the list and the player cannot disagree about what is playable. In the progress bar the three fills are **siblings positioned against the track**, never nested: 「已播」 inside 「缓冲」 means its `width: 50%` is 50% of *the buffered span*, so with buffering at 76% a click at the halfway mark drew the bar at 38% — the seek was exact, the indicator was not, which reads as "I clicked here and it jumped somewhere else" (fixed 2026-09-19; the hover tick and the time bubble take the same treatment, and both are percentages of the full track so they always point at the same place). A seek is also asynchronous, so between pointer-up and `seeked` the element still reports the *old* position — `seekTargetRef` holds the target and `timeupdate` is ignored until `seeked` lands, otherwise the bar visibly springs back before jumping forward. In **fullscreen the wrapper renders the video and nothing else**: the header row (status dot, title, ✕) is dropped rather than hidden, because it otherwise sits above the picture as a black band — which is precisely what "全屏了上面还有黑边" was. The control bar additionally stays up while the pointer rests in the bottom zone (`atBottom`), because a hidden bar is `pointer-events-none`, so a click down there falls through to the stage and silently toggles playback instead of hitting the button the user was aiming at. `OPEN_FOR_LANG = 'zh'` is the one display gate left at the top of the file: it returns `null` and skips even the `/api/sources` list fetch when the UI language is English (collections index Chinese titles and return Chinese episode names). A second, optional gate sits beside it: build-time `VITE_PLAY_PASSWORD` (added 2026-09-20) turns the section into a locked card — `PlayGate.jsx`, which carries the admin address `reel@lumenframe.cc` both on the card and inside the unlock dialog — until the password is typed once; `localStorage['lumenframe:play-unlock']` then holds the password itself, so rotating the build variable re-locks every browser. It is wired through the same `open` boolean as the language gate, so while locked the `/api/sources` fetch is never even sent. **Unset = no gate at all**, identical to `FILMGRAB_BASE === ''` and `VITE_SUPABASE_*`. Say plainly what it is: a build-time literal compiled into the JS bundle, with `/api/sources/*` still directly callable, so it deters casual visitors and nothing else — not access control, and the reason it is not a substitute for the "don't publicly deploy this" rule above. The probe is **not a control any more — it is the load strategy** (changed 2026-09-19): the section has no toolbar at all. Opening it starts the search (`onOpen`), and when that round comes back `probed: false` — the server had no probe cache, so it searched only the sites listed in `sources.json` — the client calls `/probe` and then **re-searches silently**: the list is not cleared, the sources grow in place, and no button was pressed. That `/probe` is not extra load: `doSearch` already fires `cacheProbe('all', doProbe)` in the background and `cacheProbe` is single-flight, so the frontend waits on that same round; and because `doProbe` bumps `probeGen`, the follow-up round really runs on the expanded pool rather than reading back the cold cache. Failure is not written off — `probedRef` is only set once a probe answer actually arrives, so a later 「重新搜索」 retries probe + search together. That button is the one manual entry left: it lives **inside** the empty/error hint, where a search that failed (site timeouts, backend down) is the only thing that can happen, and it is not shown otherwise. The liveness table was already deleted because probe `ok` only means the list endpoint answered, **not** that it has your film, and those aliases are neither readable nor clickable. Junk entries (`[电影解说]`, `[预告片]`) are separate `vod` rows scored **identically to the real film** (0.8), so `isJunkEntry` drops them in `searchOne` before `seen.add(vodId)`. It matches `type_name`/`vod_remarks` bare, but `vod_name` **only inside brackets** (`JUNK_TAG_RE`) — a bare match kills real features whose titles contain those words (`记忆碎片`, `预告犯`, `爱情短片`). Do not add line-level filtering on top: 14 kept play-groups were checked and none carried a commentary label, because these sites mint a new `vodId` rather than adding a play group.

### Python service (`filmgrab-service/`)

`main.py` holds the FastAPI app plus the FilmGrab routes; `filmgrab_scraper.py` and `youtube_service.py` are the scrapers. Everything else under `routers/`, `torrents/`, `helper/`, `constants/` is the vendored Torrent-Api-py code, mounted under `/api/torrent/v1/*` and gated by `authenticate_request` (which is a no-op unless `PYTORRENT_API_KEY` is set).

- FilmGrab returns 403 to ordinary clients — `curl_cffi` with `impersonate="chrome"` is load-bearing, not an optimization. Title matching uses a 0.85 similarity threshold with year hard-reject and Roman-numeral normalization (`titlematch.js` on the Node side mirrors this intent, different implementation).
- `/api/proxy` is whitelisted to `film-grab.com` `/wp-content/uploads/` paths, with `asyncio.Semaphore(PROXY_CONCURRENCY)` limiting upstream concurrency. It also takes `s=thumb`, which swaps `photo-gallery/<name>` for the site's own `photo-gallery/thumb/<name>` (500px / 54-91 KB vs the original's 1023-1280px / 152-299 KB — measured 2026-09-25, ~−53% bytes for a whole 65-still grid) and **falls back to the original** if the variant can't be derived or 404s, so a missing thumbnail never blanks a tile. `screenshots` still lists originals; only the grid appends `&s=thumb` — the lightbox and the canvas card deliberately keep full resolution for export.
- In-memory caches: screenshots 6h, image binaries 1h LRU/120, trailers 7d, comments 1d.
- **Personal use only** — FilmGrab prohibits scraping. Bind to `127.0.0.1`, never expose :8000. Public deployments should simply not run this service; the Film Stills section self-hides when `FILMGRAB_BASE` is empty.

## Cross-cutting gotchas

- **TMDB's zh-CN genre list has holes: TV genres 10765 (`Sci-Fi & Fantasy`) and 10768 (`War & Politics`) come back in English from `/api/genres?lang=zh-CN`** — every other movie/TV genre is translated. Display names for `/api/genres` rows therefore go through `genreDisplayName(genre, t, kind)` (`web/src/genres.js`), which overrides exactly those two ids from the `tmdbGenre.10765/10768` i18n keys. It also accepts a bare English genre name (TVmaze genre strings on detail chips, old links), resolving it through the static tables to the same id override; anything else passes through untouched, because `t()` on a missing key returns the key string itself — so the override must only query ids known to be untranslated. QuizRecommender's chips are a separate mechanism: its genre list is hardcoded English (not `/api/genres`), so every name is keyed as `quiz.genre.<Name>` in both dictionaries.
- **Anything that queries an English-only upstream by title must use `movie.title_en || movie.title`**, never the localized `movie.title`. This applies to torrent search, OpenSubtitles, ShotOnWhat, Rotten Tomatoes, TasteDive, FilmGrab stills, and IMDb-keyed lookups — i.e. every external service except TMDB itself. Both `/api/movie/:id` and `/api/tv/:id` emit `title_en`; the `|| movie.title` half is not decoration, because a TV page in Chinese now has a Chinese `title` and would otherwise send `q=神探夏洛克` to torrent sites that index English release names. `FilmGrabShots.jsx` was the lone holdout until 2026-09-25: in the Chinese UI it searched `q=盗梦空间`, FilmGrab returned nothing, and the section rendered 「暂无该片的剧照」 — indistinguishable from "the site hasn't got this film", which is why it went unnoticed. When adding a section, grep the siblings (`Torrents.jsx`, `Subtitles.jsx`, `AlsoLiked.jsx`) for the pattern rather than re-deriving it. Because `title_en` is language-independent, such a component also won't re-fetch (and won't clear its results) when the UI language changes. The mirror image is **`/api/sources/search`**, which needs *both* names and sends them as separate `q=` queries (see `PlaySources.jsx`) — the Chinese name is what makes Chinese collection sites return the right show, and the English one widens the net; sending only the English name is why a Chinese-language TV page used to come back with 女神探夏洛克 and 少年神探狄仁杰 instead of the show itself.
- **Canvas export requires proxied images.** TMDB and TVmaze images must be loaded through `/api/image` and `/api/tv/image` with `crossOrigin="anonymous"`; pointing an `<img>` at `image.tmdb.org` directly makes the canvas tainted and silently breaks card export. Both backends emit `Access-Control-Allow-Origin: *` for the cross-domain (GitHub Pages + separate API) deployment.
- **`FILMGRAB_BASE` semantics**: dev defaults to `/filmgrab` (Vite proxy), production defaults to `''` = disabled section. Distinct from `API_BASE`, which is `''` = same-origin in dev.
- **The Node and Python trailer endpoints are different things**: `/api/trailer/{tmdbId}` (Node, TMDB video keys, free) supplies the initial key; the Python `/api/trailer` is the YouTube Data API path used for comments. YouTube quota is 10k units/day with `search.list` costing 100 — hence the 7-day trailer cache.
- `docs/` is gitignored, so it is local-only documentation that will not appear in a fresh clone. It is nonetheless the authoritative reference: `docs/api-reference.md` (every endpoint with shapes), `docs/tech-stack.md` (data sources + full cache table), `docs/deploy.md` (Nginx/systemd/GitHub Pages), and `docs/*.md` design notes for individual features.
- A `?? .trae/documents/` directory holds older design notes for in-flight work.
